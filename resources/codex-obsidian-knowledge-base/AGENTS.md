# AI 学术知识库维护规则

本文件是 Codex 在此 Obsidian vault 中工作的项目级规则。目标是把可信原始资料逐步编译为可追溯、互相链接、可持续维护的学术 Wiki，而不是生成一堆彼此孤立的摘要。

## 角色与边界

- 用户负责选择资料、判断研究价值、决定研究方向和批准有争议的结论。
- Codex 负责读取、归档、摘要、交叉引用、更新索引、记录变更和执行健康检查。
- `10-原始资料/` 是事实来源层。除非用户明确要求整理文件名或补充元数据，不得改写、覆盖或删除其中的原始资料。
- `20-知识库/` 是 Codex 维护的编译层。可以新建和更新页面，但必须保留来源追踪。
- `30-研究项目/`、`40-实验记录/` 和 `50-成果输出/` 是人机协作层。重要判断、研究结论和对外输出应由用户复核。
- 不得伪造论文、作者、DOI、实验结果、引文、页码或访问日期。不确定时明确标注“待核验”。

## 目录约定

| 路径 | 用途 |
|---|---|
| `00-收件箱/` | 尚未处理的想法、链接、临时笔记 |
| `10-原始资料/` | PDF、网页剪藏、课程材料、数据说明等不可变来源 |
| `20-知识库/文献笔记/` | 每个来源的结构化阅读笔记 |
| `20-知识库/概念/` | 方法、模型、理论、指标等原子概念页 |
| `20-知识库/主题综述/` | 跨来源综合、比较、研究脉络与争议 |
| `20-知识库/实体/` | 数据集、人物、机构、会议、工具等实体页 |
| `30-研究项目/` | 研究问题、计划、里程碑、决策 |
| `40-实验记录/` | 可复现实验记录 |
| `50-成果输出/` | 报告、讲稿、论文草稿等派生输出 |
| `60-每日笔记/` | 每日捕获、阅读和研究日志 |
| `90-系统/模板/` | Obsidian 模板 |
| `90-系统/附件/` | 图片等通用附件 |

## 通用写作规范

- 使用 UTF-8 Markdown、Obsidian `[[双向链接]]` 和 YAML properties。
- 一页聚焦一个主要对象；标题必须能脱离文件夹独立理解。
- 首次出现且值得单独解释的稳定概念，应链接到概念页；不要为了增加链接而链接普通词。
- Wiki 页面优先写综合后的知识，不大段复制来源原文。
- 直接引语必须简短，并注明来源位置；能够转述时优先转述。
- 数学符号使用 LaTeX；代码注明语言；实验数字注明数据集、切分、指标和条件。
- 元数据至少包含 `type`、`status`、`created`、`updated`、`tags`。日期格式为 `YYYY-MM-DD`。
- `status` 使用：`seed`、`developing`、`verified`、`stale`、`archived`。
- 标签只做粗粒度分类，语义关系主要使用双链表达。

## 来源与引用

- 每个文献笔记必须指回 `10-原始资料/` 中的文件或一个稳定 URL。
- 概念页和综述页的可核验主张，在“证据与来源”中列出对应文献笔记或原始来源。
- 区分：
  - **来源陈述**：资料明确支持；
  - **综合判断**：多个来源综合得到；
  - **研究假设**：尚待实验验证；
  - **个人想法**：用户或 Codex 的探索性推断。
- 来源冲突时不要强行统一；记录双方结论、条件差异和待核验项。
- 网络事实如可能变化，检索时记录访问日期；学术结论优先引用论文、官方文档或原始数据。

## 摄取流程

当用户说“摄取/归档/整理这个资料”时：

1. 确认资料位于 `00-收件箱/` 或 `10-原始资料/`；若在收件箱，移动前先判断类型。
2. 读取资料，提取研究问题、方法、数据、核心结论、限制和可复现信息。
3. 在 `20-知识库/文献笔记/` 创建或更新一篇文献笔记。
4. 更新相关概念、实体和主题综述；避免重复页面，先搜索同义标题和 aliases。
5. 在 `知识库首页.md` 的索引中加入新页面的一行说明。
6. 在 `变更日志.md` 追加一条 `## [YYYY-MM-DD] ingest | 标题` 记录。
7. 汇报修改了哪些页面，以及仍需用户判断的问题。

默认一次处理一个来源；批量处理必须先说明范围，并保持逐来源可追踪。

## 查询流程

当用户针对知识库提问时：

1. 先读 `知识库首页.md`，再搜索相关 Wiki 页面。
2. 必要时回到对应原始资料核验，不只依赖摘要。
3. 回答中区分已知事实、综合判断和推测，并给出 vault 内链接。
4. 若答案形成了可复用的新综合，经用户同意后写入主题综述或成果输出。
5. 若写回，更新首页索引与变更日志。

## 健康检查流程

当用户说“巡检/健康检查/lint 知识库”时，检查：

- 无来源支撑的事实性主张；
- 指向不存在页面的链接；
- 没有入链且不属于原始资料、模板或每日笔记的孤立页面；
- 重复概念、同义标题和不一致 aliases；
- 新来源已经推翻但仍未更新的旧结论；
- 缺少 `type`、`status`、`created`、`updated` 或 `tags` 的 Wiki 页面；
- 文献笔记存在但首页索引或变更日志缺失；
- 重要概念被多次提到却没有独立页面。

先报告问题，再做大范围重构。删除、合并或批量改名必须征得用户同意。

## 变更日志格式

只在 `变更日志.md` 末尾追加，格式固定：

```markdown
## [YYYY-MM-DD] ingest | 标题

- 来源：[[来源或文献笔记]]
- 新建：[[页面]]
- 更新：[[页面]]
- 待办：需要用户判断的事项；没有则写“无”
```

其他操作把 `ingest` 替换为 `query`、`lint`、`experiment` 或 `maintenance`。

## 完成检查

每次知识库写入结束前确认：

- 新结论能追溯到来源；
- 双链目标存在或明确作为待创建页面；
- 首页索引已更新；
- 变更日志已追加；
- 未改写原始资料；
- 没有把推测写成事实；
- 仅修改完成当前任务所必需的文件。
